# Report specification (8 pages)

Conventions: **DS** = data source; **Dim** = dimension; **Metric** = metric; filters list *beyond* the page controls (date range + channel unless noted). "Takeaway box" = the business explanation to put in a text box or chart description (wording describes what to look for; read the actual numbers from your charts).

## Page 1 — Executive Growth Overview
Question: *Is growth efficient, and what should leadership do next?*
| Element | Type | DS | Config | Business explanation |
|---|---|---|---|---|
| KPI row: Media spend, New paying customers, Paid-media CAC, ROAS 12m (observed cohorts), LTV:CAC 12m | 5 Scorecards | `rpt_marketing_daily` | SUM(spend_usd); SUM(new_customers); calc fields; add "compared to previous period" off for ratios | ROAS and LTV:CAC use only fully observed cohorts, so the newest months are excluded on purpose. |
| Spend vs customers by month | Combo (bars + line) | `rpt_marketing_daily` | Dim `month_start`; Metric SUM(spend_usd) bars, SUM(new_customers) line | Customers lag spend by weeks (trial + journey), so single months are noisy. |
| Paid-media CAC vs fully loaded CAC | Line | `rpt_unit_economics_monthly` | Dim `acquisition_month`; Metrics CAC fully loaded (calc) and Paid-media CAC (calc); filter channel is paid (`spend_usd > 0`) | The gap is non-media overhead — leaders often quote the lower number. |
| LTV:CAC by channel | Bar + reference line 3 | `rpt_marketing_daily` | Dim `channel_name`; Metric LTV:CAC 12m; sort desc; filter `is_paid`-type: create filter `spend_usd > 0` | Below ~1.5 a channel struggles to pay back; above 3 is a scale candidate *if incrementality and saturation allow*. |
| Recommended actions | Table | `bi_recommendations` | Dims channel, recommended_action, evidence, caveats | Generated by rules over calculated results, not opinion; caveats include experiment and MMM evidence. |
| Freshness | 2 Scorecards | `bi_data_freshness` | `data_end_date`, `pipeline_finished_utc` | If the pipeline date is old, the report is stale (see refresh guide). |

## Page 6 — Incrementality
Question: *Did marketing cause extra conversions?* No date control (experiments are fixed events).
| Element | Type | DS | Config |
|---|---|---|---|
| Experiment results table | Table | `bi_experiment_results` | experiment_id, experiment_name, rate_control, rate_treatment, Lift label, p_value, incremental_roas, attributed_roas, verdict |
| Attributed vs incremental ROAS | Clustered bar | `bi_experiment_results` | Dim experiment_name; Metrics attributed_roas, incremental_roas |
| Lift with CI | Bar with error bars *or* table + bullet text | `bi_experiment_results` | rel_lift with rel_lift_ci_low/high (Looker Studio bar charts support error bars only through "Reference lines"; a table with conditional formatting on whether the CI spans 0 is simpler) |
| Power | Scorecards | `bi_experiment_results` | mde_relative, n_treatment |
| Geo-lift test | Time series | `bi_geo_lift_weekly` | Dim week_start; Metric indexed_to_pre_period; breakdown assigned_group; reference line at test start |
| Geo-lift result | Scorecards/table | `bi_geo_lift_results` | rel_lift (+CI), p_value_randomisation, parallel_trends_ok, incremental_roas, verdict |
| Lifecycle (CRM) results | Table | `bi_lifecycle_results` | metric, horizon_days, control, treatment, rel_lift, p_value |
| Lifecycle value by horizon | Column | `bi_lifecycle_value` | Dim horizon_days; Metrics incremental_gross_profit_per_assigned_user, net_value_per_treated_user; show persistence_note |
Explanation: experiments are the only causal evidence here. A significant lift can still be unprofitable on first payments; compare with LTV. Lifecycle incrementality shows lift decaying when program-driven customers retain worse.

## Page 7 — MMM & Budget Scenarios
Question: *Which channels drive revenue and how should the budget move?* No date control for model outputs.
| Element | Type | DS | Config |
|---|---|---|---|
| MMM inputs | Time series | `rpt_mmm_weekly` | Dim week_start; Metrics spend_* (stacked) and new_mrr_usd (line) |
| Model comparison | Table | `bi_mmm_model_comparison` | model, test_rmse, test_mape, test_r2, chosen_for_decisions |
| Actual vs fitted | Time series | `bi_mmm_fit` | new_mrr_usd, fitted; shade test period via `is_test_period` (breakdown) |
| Decomposition | Stacked area | `bi_mmm_contributions` | Dim week_start; breakdown component; Metric SUM(contribution_usd) |
| Channel contribution with uncertainty | Table + bars | `bi_mmm_channel_summary` | channel, Share label, avg_roi, avg_roi_p05, avg_roi_p95, lag_weeks, share_of_draws_at_zero |
| Response curves | Line | `bi_mmm_response_curves` | Dim weekly_spend_usd; Metrics weekly_mrr, p05, p95; control channel |
| Budget scenarios | Table | `bi_mmm_scenarios` | scenario, weekly_budget_usd, Delta label, prob_better_than_current |
| Spend by scenario | 100% stacked bar | `bi_mmm_scenario_spend` | Dim scenario; breakdown channel; Metric weekly_spend_usd |
| Calibration vs experiments | Table | `bi_mmm_calibration` | channel, experiment_type, experiment_incremental_roas, mmm_avg_roi (+p05/p95), reading |
| Diagnostics | Table | `bi_mmm_diagnostics` | check, value, status, meaning; colour status |
Explanation box: *MMM estimates are model-based associations (not causal proof) fitted to synthetic data; intervals reflect coefficient uncertainty only; if the experiment disagrees with the MMM, trust the experiment and use it to recalibrate. A budget shift is a hypothesis to test.*
